# 实验：题目语言 A/B（中文 vs 英文）

> 起因：`jev-chat-jarvis` 的"已知限制"里写着 **「Jev 主训练语言是英文，题目用英文、聊天内容保留中文」**。
> 我们插件从 v1.0 起题目全是中文，这条情报如果成立，等于白丢准确率。所以实测一次。

## 方法

- 同一批 **10 个用例**（覆盖催办 / 闲聊 / 诈骗 / 验证码 / 情侣 / 家人 / 客户），**聊天内容一律保持中文**，只换题目语言。
- 三个变体，每个用例重复 **3 次**（顺便量稳定性），共 **90 次调用**，并发 6，总耗时 21 秒。

| 变体 | instructions | criteria 键 | 说明 |
|---|---|---|---|
| `zh` | 中文 | 中文 | 当前插件用的 |
| `en` | 英文 | 英文 | Jarvis 的做法（选项用英文键，值映射回中文） |
| `mix` | 英文 | 中文 | 折中 |

- 打分只用**能判对错**的题，避免自说自话：`urgency`(score 0~3 → MAE)、`need_reply`(noul → 准确率)、
  `risk`(noul → 准确率)、`emotion`(choice，少数用例有人为期望值 → 准确率)。
- 另统计：解析成功率、choice 题 top1 平均置信度、3 次重复一致率、变体间 top1 一致率。

## 结果

| 指标 | zh | en | mix |
|---|---|---|---|
| 解析成功率 | 100% | 100% | 100% |
| **着急 MAE（越小越好）** | **0.36** | 0.44 | 0.42 |
| 待回复 准确率 | 90% | 90% | 90% |
| 风险 准确率 | 100% | 100% | 100% |
| 情绪 准确率 | 100% | 100% | 100% |
| **情绪 top1 平均置信度** | 0.808 | **0.905** | 0.822 |
| **3 次重复 top1 一致率** | **97%** | **97%** | 93% |
| **合成客观分** | **0.945** | 0.938 | 0.940 |

变体间标签一致率（情绪/意图/姿态，10 用例 × 2 题 = 20 项）：

| 对比 | 一致率 |
|---|---|
| `en` vs `zh` | **13/20 = 65%** |
| `mix` vs `zh` | **19/20 = 95%** |
| `en` vs `mix` | 13/20 = 65% |

## 结论

1. **"英文题目更准"不成立** —— 客观分三者持平（0.938~0.945），差异在噪声范围内。
   英文唯一的好处是 **top1 置信度更高（0.905 vs 0.808）**。
2. **但英文题目会改变结论本身**：`en` 与 `zh` 在 35% 的题目上选出了**不同的标签**。
   换句话说英文不是"更准"，而是**更武断** —— 置信度上去了，标签也漂了。
   `mix`（英文提问 + 中文选项）与 `zh` 有 **95%** 一致，是安全的折中。
3. **决定：默认沿用中文题目**（`zh`）。理由：客观分最高、稳定性并列最高、且与插件版口径一致
   （两个版本数据可比）。同时在新版里留一个 `prompt_lang` 设置项（`zh` / `mix` / `en`），
   谁想自己复现这个实验，改一个字母就行。
4. 附带发现：
   - **风险题是强项**：冒充领导骗钱 0.93~0.95、索要验证码 0.90~0.90，三变体全对。
   - **「在吗？」被高估成"着急 0.59~0.81"**（应为 0）：中文口径已经是三者中最克制的，但仍然偏。
   - **「记得吃饭，别熬夜」情绪判成"焦虑"**：模型把它读成说话人焦虑 —— 合理但反直觉，值得在界面上给前三名而不是只给第一名。
   - 唯一一处待回复判错是「哈哈哈那个视频太搞笑了」（0.51 擦线判"要回复"），属边界样本。

## 复现

```bash
python jev_ab_probe.py     # 需要 curl_cffi，key 从插件 config.properties 读
```

原始数据：`ab_raw.json`（90 条答案的完整 JSON）。
