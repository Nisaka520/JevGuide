# JevGuide —— 读屏与判读设计

> **一句话**：把 JevIntent（Xposed 插件版）的判读能力，用**无障碍服务**重新实现一遍：
> 只读屏、只弹 3 条 Toast、不生成文案、不发送、不悬浮窗。
> 与插件版**完全独立**的两个项目（不同仓库、不同代码、可同时安装）。

## 1. 为什么做（思路来源与边界）

思路来源：[jev-chat-jarvis](https://github.com/jev-chat/jev-chat-jarvis)（⭐3.5k）验证了
**「无障碍只读屏幕 + Jev 判定」这条路在安卓上是可行的**，而且不需要 hook 微信、不需要 FkWeChat。
这一点值得搬过来。但它是"对话副驾"（悬浮窗 + 候选回复 + OCR + 知识库），我们只需要其中的**判读那一层**。

**独立实现的边界（避免被认定抄袭）**：

| 维度 | jev-chat-jarvis | 本项目 |
|---|---|---|
| 交互 | 半透明悬浮窗，常驻 | **只有 3 条 Toast**，无悬浮窗、无常驻 UI |
| 输出 | 判断 + 3 条候选回复（第二个文本模型起草） | **只有判断**，不生成任何回复文案 |
| 采集 | 无障碍树 + **截图 ML Kit OCR 兜底**（APK 27MB） | **只读无障碍树**，不做截图/OCR（更小、更少权限） |
| 触发 | 前台自动 + 悬浮窗手动 | 无障碍按钮 / 磁贴 / 常驻通知 / 可选自动（防抖） |
| 关系 | 联系人表 + 知识库笔记 + 历史 | 联系人表（别名 → 关系/性别/备注），**无知识库** |
| 场景 | 微信/QQ/X/飞书，含群聊 | **只做微信单聊** |
| 依赖 | Kotlin + AndroidX + ML Kit | **零第三方依赖**（只用 `org.json` + `HttpURLConnection` + 原生 View） |
| 代码 | 自有实现 | 全部自写：命名、结构、文案、图标均不同 |

概念（"读屏 + 调 LLM 判读"）不受版权保护；**代码与文案是**。所以本项目不复制对方任何一行代码、
不沿用对方文案，README 里显式致谢并链接原项目以说明区别。

## 2. 功能范围

**做**：
- 读当前微信单聊窗口的**可见消息**（谁说的 + 内容 + 是否带引用）。
- 调 Jev 一次（7 题），拿到：意图、情绪分布、着急分、是否待回复、风险、建议、回复姿态。
- **固定弹 3 条 Toast**（口径与插件版一致，两版数据可比）：
  1. `意图：… 85%` ⏎ `情绪：平静 56% · 客套 42% · 着急 2%`
  2. `着急：不着急 · 0.48/3`
  3. `建议：正常交流 90%`
- 关系按会话匹配（别名表 → 关系 10 档 + 性别 + 备注），备注作为 `background` 进 state。
- 本机保存：联系人表（JSON）、接口密钥、开关；可一键清空。

**不做**：候选回复/文案生成、自动发送、OCR、群聊、悬浮窗、知识库、云同步。

## 3. 架构

```
微信窗口 ──(AccessibilityEvent)──▶ WatchService
                                     │ ① 抓当前窗口：标题 + 可见消息列表（去重、判我方/对方）
                                     ▼
                              Digest(标题, 对方名, 消息[])
                                     │ ② 关系匹配：Contacts.match(标题|对方名) → 关系/性别/备注
                                     ▼
                              JevClient.analyze(state)   ← 7 题（Prompt.kt，默认中文）
                                     │ ③ 解析 answers → Verdict
                                     ▼
                              Toast3.show(verdict)       ← 固定 3 条，间隔可设
```
- **纯逻辑层**（`Prompt` / `JevClient` / `Contacts` / `Digest` / `Verdict`）不依赖 Android SDK，
  可在 JVM 上跑单元测试（与插件版"能在电脑上测完整流程"的做法一致）。
- **Android 层**只做三件事：抓屏、取配置、弹 Toast。

## 4. 触发方式（4 选 1，都可关）

| 方式 | 说明 |
|---|---|
| **无障碍按钮** | 系统无障碍快捷键（三指长按/导航栏按钮）触发一次分析 |
| **快捷设置磁贴** | 下拉通知栏点"旁白一下" |
| **常驻通知** | 服务运行时挂一条通知，点一下分析（可关） |
| **自动**（设置里开） | 检测到对方新消息 → 防抖 1.2s → 自动分析（默认**关**，避免打扰） |

## 5. 提示词语言

结论来自实测（见 [`实验-题目语言AB.md`](实验-题目语言AB.md)）：**默认中文**（客观分最高、稳定性并列最高、
与插件版口径一致）。设置里留 `prompt_lang = zh | mix | en` 三个选项，方便任何人复现该实验。

## 6. 技术约束

- `minSdk 26`（Android 8.0）、`targetSdk 35`、Kotlin、**无 AndroidX**。
- 权限：`BIND_ACCESSIBILITY_SERVICE`（必须）、`POST_NOTIFICATIONS`（通知，可选）、`INTERNET`。
  **不申请**读取通知、不申请截屏、不申请存储。
- 构建：本地 `gradle assembleDebug`；CI 用 GitHub Actions 出 APK（tag → Release）。
- 密钥只存本机 `SharedPreferences`，**不进任何仓库**（仓库里只有 `check_secrets` 自检）。

## 7. 与插件版的取舍

| | JevIntent（插件版） | JevGuide（本项目） |
|---|---|---|
| 前置 | 需要 FkWeChat + LSPosed | 只要系统无障碍 |
| 拿到的数据 | 消息对象（精确、含引用块、可回溯历史） | 屏幕上的可见文字（会被截断） |
| 稳定性 | 微信更新易失效 | 无障碍同样会被微信混淆影响，但适配面更窄 |
| 风险 | hook 宿主 | 只读，不注入 |

两版共用同一套**判定口径**，但代码零共享（一个 bsh 单文件，一个 Kotlin 工程）。
